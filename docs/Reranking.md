# Reranking — 検索結果の再ランク付け

**Reranking** は、一度取得した検索結果をより精密なモデルでスコアリングし直す技術です。

## なぜRerankingが必要か？

- **1次検索（埋め込みベクトル）**: 高速だが、細かいニュアンスを捉えきれない
- **Reranking（再評価）**: クエリと各ドキュメントを**直接比較**して関連性を再評価

2段階のフィルタリングで、精度と速度を両立します。

## 2つのRerankerモデル

### BGE Reranker（推奨）
- **軽量で高速**: CPUでも実用的な速度
- **FlagEmbeddingライブラリ**を使用
- 通常の用途では十分な精度
- 初めてRerankingを試す方におすすめ

### Cross-Encoder
- **より高精度**: クエリとドキュメントをTransformerで直接比較
- **要GPU推奨**: CPUでは時間がかかる場合がある
- 精度重視のシチュエーションに向いている

## LocalNoteでの動作

```
1次検索（ChromaDB）
    ↓ K×2件取得（多めに取得）
Rerankerで全件スコアリング
    ↓
スコア順に並び替え
    ↓
上位K件をLLMに送信
```

## 設定のコツ

- **資料が多い場合** → Reranking有効で精度向上
- **資料が少ない場合** → Rerankingなしでも十分
- **速度重視** → Rerankingオフ
- **精度重視** → cross-encoder + Rerankingオン
